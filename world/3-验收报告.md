## B. 只是演示 / 有明确限制的部分

1. **召回与关系类型判断是离线启发式**，不是 AI。
   算法：中文二元组 + IDF 加权 + 标题加权 + 未完成加分 + 焦点加分 + 时间衰减。
   实测质量：
   - 「RL-app 语音入口」第 1 名正确（252 分，高相关）
   - 「AI 终端硬件」第 1 名正确（211 分，高相关）
   - 「Ab Initio」最高只有 82 分（中相关），界面明确提示
     *"召回到的旧节点相关度都不高……建议存为待分类探索"*，且**不自动预选父节点**。
     这是正确行为——RL-data 里确实没有 Ab Initio 相关的旧问题。
   - 已知噪声：「RL-app」查询里「人与关系 2026-07-11 爱情…」排到第 2（115 分）。
     原因是「真正 / 入口 / 语音 / 思考」这类词的词面重叠。界面给了相关度和命中词，可人工排除。
2. **导入时的 7 条候选跨日关联是我根据真实记录人工写的理由**，不是模型生成的。
   它们默认全部待确认，不计进度。
3. **语音按钮**用的是浏览器 Web Speech API（本地听写），不是接入语音模型。
4. **第一版靠粘贴对话文本导入**，实时语音连接是后续能力。

## C. 需要真实 AI API 才能做到的

| 功能 | 为什么必须要 API |
|---|---|
| 真正理解意图（"为什么这件事让你感到意外"） | 需要语义理解，词面重叠做不了 |
| 跨语义召回（Ab Initio → 商业模式旧判断） | 需要向量/语义检索，词面必然召不回 |
| 自动写出「它为什么能推进旧问题」 | 现在这一栏必须人手写 |
| 从长对话里自动切分出多条认识 | 现在一次只处理一段 |
| 实时语音对话 | 需要语音模型 |

**不需要 API 的**：导入、稳定 ID、关系存储、确认流程、全体像、逐层深入、历史回放、3D 世界。
这些现在就在真实数据上跑着。

## D. 还没有验证的

1. **14 天使用验证**（关联被接受/纠正率、真实跨日连接次数、无效强连次数、次日恢复耗时、实际认知修正与现实行动、操作负担）——需要真实使用，不能在代码里证明。
2. **写回 GitHub 的冲突处理 / 回读校验 / 旧版本保留**——本版完全只读，这套机制尚未实现，也未测试。
3. **隐私与合规**——按来源和敏感度控制哪些内容可发给 AI 的机制未实现。journal 11/07 自己就记了这条，目前仍未解决。
4. **多用户 / 其他人的数据**——只在一个人的真实数据上跑过。
5. **移动端实机**——只在 1440×900 的 Chromium 里验证过，CSS 有移动断点但没上真机。

## E. 测试发现的问题

1. **Today 指针落后 36 天**（最严重）。原型会把 wealth 10/02 当成当前焦点，和真实进度完全脱节。已做成开屏告警，但 RL-data 本身的指针仍需修正。
2. **89 条 rows 里只有投资的 28 条有父节点字段**。其余 61 条在数据层就没有归属。这不是导入器的问题，是数据模型的缺口。
3. **五个项目的完成判据互不相同**，任何统一进度条都会算错。已按项目各自的 `done` 处理。
4. **夜间分析在数据里几乎没留下成功记录**（`status.json` 只剩一条 late=true）。本版不依赖它。
5. **召回噪声**（见 B.1）。已通过 IDF + 相关度标注 + 低相关不预选 缓解，未根治。
