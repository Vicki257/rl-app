# 第一步：独立诊断

读的是 RL-data `7e37c86` 的真实数据：27 个 JSON、483 条记录、5 个项目、
89 条 rows、55 条 history、184 条 methods、16 份公司研究档案、4 条逻辑链。

## 一、结构性根因（不是功能缺失，是数据模型缺失）

**根因：RL-data 里有「记录」，没有「关系」。**

每条 row 的字段是：`date / f / q / cols / ev / closedAt`。
没有任何字段能表达「这条认识和哪条旧认识有关、是什么关系、为什么有关」。
所以：

1. **跨日连接在数据层根本不存在**，不是没做界面。
   唯一的归属字段是投资项目的 `rows[].main`（28 条里 28 条有），
   其他四个项目的 89 条 rows 里，**没有一条带父节点**。
   导入后实测：rl 11 条未完成问题全部是孤儿，wealth 4 条、people 3 条同样。
   这就是痛点一的机械原因——不是用户不写，是没地方写。

2. **「深入」和「新开」在数据上无法区分。**
   `tracks[].sops[].nodes/edges` 确实存了层级（AI 深度思考 V2 共 8 层、教育 V4 共 6 层），
   但那是 SOP 模板的层级，不是某个具体问题的推进。
   rows 之间没有 edges，所以"今天这条是不是真的更深了"没有数据可判。

3. **指针会和真实进度脱节，而且没人发现。**
   实测：`global.json.current = wealth`、`widget.json.project = wealth`，
   焦点日 **2026-10-02**；而真实最新记录是 journal **2026-11-07**（6 条）和 rl **2026-11-03**。
   指针落后 36 天。新版把这条做成了开屏告警。

4. **夜间 AI 写入不稳 → 重要认识没沉淀**，在数据里留下了痕迹：
   rl rows[1]「夜间分析一次都没跑过，矛盾/结果/召回三张卡全是空的」，
   `status.json` 里只剩一条 people 的 nightQueue 记录（10/26，late=true）。
   方法库 m-095 自己写过结论：工具不稳就降级，别停。
   **但「AI 自动写」这件事本身从来没被降级**——这是失败重复的地方。

5. **各项目判据不一致，而系统默认它们一致。**
   实测五个项目的 `done` 完全不同：
   rl=`够用了/不做`，投资/财富/人与关系=`已确认/已被推翻/不做`，journal=`已记录`。
   `ev`（0–5）只有投资、财富、人与关系三个项目有，rl 和 journal 没有。
   任何「统一进度条」都会算错。

## 二、已经有的能力（不要重做）

- **无损的原始历史**：rows/history/methods/cos 都带日期和出处，深层材料完整
  （平安レイサービス那份档案有 7 个 step、12 行 meta、首个 step 的 data 字段 263 字）。
- **每个项目自己的现实判据**：rl 的 `reality` 字段写得非常硬（"和 AI 讨论不算"）。
- **方法库 184 条带 refs 回指日期**，是现成的召回素材。
- **两条逻辑链本身就是可复用的思考方法**，不需要重做。
- **判断卡（iteration.gates）已有 decision 结构**，是现成的「取舍」事件模型。

## 三、仍然缺的机制

| 缺什么 | 为什么必须有 |
|---|---|
| 边（关系）+ 必填理由 | 没有理由的连接就是关键词分类，正是要避免的 |
| 关系类型 / 认知事件 / 证据状态三者分开 | 混成一个字段就会把"提出子问题"算成"已经更深" |
| 稳定记录 ID | 同一天多条（journal 11/07 有 6 条），日期不唯一；下标会被插入和重排改掉 |
| 用户最上层核心欲望 | 数据里不存在这个字段，各项目 goal ≠ 总目标 |
| 待分类队列 | 关联不确定时的去处，否则只能强连或丢弃 |

## 四、对原方案里过度简化之处的审查

1. **「七层深度」不能当模板。** 数据实测深度：投资 12、rl 7、财富 1、人与关系 1、日志 1。
   把所有项目套成 7 层会凭空造出不存在的深度。新版深度一律由已确认的 `deeper` 边算出。
2. **「五个研究区域」是原型的硬编码。** 项目必须从 `projects/index.json` 发现，现在是 5 个，以后会变。
3. **「AI 自动分类 / 自动写入」是已经失败过两次的路径**（m-095、rl rows[1]）。
   新版把 AI 的权限压到只能**提案**，确认权在用户，且没有理由就连不上。
4. **「生长动画」不能当成功证据。** 新版的建筑高度是 `16 + 未完成数 + 已确认深度 + 已确认关系数` 的函数，
   确认一条关系后 journal 的楼从 18 长到 19——因为数据变了，不是因为播了动画。
5. **「统一总目标」不能自动合并。** 中央主殿在核心欲望未确认前只建基座，不建高塔。
