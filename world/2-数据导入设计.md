## 2. 稳定 ID 方案

```
ID = kind + ':' + proj + ':' + date + ':' + h8(内容)        h8 = FNV-1a 32 位取 8 位十六进制
```

- **日期不能单用**：journal 2026-11-07 当天就有 6 条。
- **下标不能当长期 ID**：插入、重排、迁移都会改。下标只写进 `src.idx`，作溯源用。
- **重复导入**：指纹相同 → 命中同一节点，不新建（实测重复 runImport 后记录数不变）。
- **指纹相同但内容不同** → 另立一条并写进「重复清单」，**绝不静默合并**。
- **来源变化识别**：每条记录带 `src.path + src.idx + raw`，原文随时可比。

## 3. 兼容已有主线结构

直接复用、不另造：
`project.mainline` / `sop.nodes+edges` / `tracks` / `mains` / `rows[].main` / `current.focus` / `iteration.gates` / `history` / `methods`。

但严格区分：

- **SOP 流程节点 ≠ 认知问题节点** —— 单独 `kind:'sopnode'`，不进问题树。
- **history ≠ 已验证的认识** —— 单独 `kind:'hist'`，默认无证据状态。
- **项目 goal ≠ 用户最上层核心欲望** —— 核心欲望是空的，等用户确认。
- **不同项目的研究方向不自动并入一个总目标**。

## 4. 自动建初始认知地图的边界

只有**数据里直接写了**的关系才建成「已确认」边：

- `mainline.main` 挂在 `project.goal` 下 —— project.json 自己的层级。
- `rows[].main` → 对应 `mains[]` —— 投资 28 条全部有，直接连。
- `tracks[].sops[].edges` —— 逻辑链自带的边，按原边导入。

**写不出理由的一律不连**，进入「待分类探索」。实测结果：

```
待分类（孤儿）未完成问题：rl 11、wealth 4、people 3、quant 0、journal 0
```

候选跨日 / 跨项目关联共 7 条，全部来自真实记录，**默认 100% 待确认**，
不计入任何进度。找不到对应记录的候选会进待处理队列（实测为 0）。

## 6. 缺失与冲突处理

| 情况 | 处理 |
|---|---|
| 项目缺某个文件 | 记进「缺失文件」清单，不报错不补零 |
| rows 某行没有问题文本 | 进待处理队列，不建认知节点 |
| 指纹冲突 | 另立一条 + 记进重复清单 |
| 候选关联找不到真实记录 | 进待处理队列，不建边 |
| 指针日期 < 最新记录日期 | 进「指针滞后」清单，开屏告警 |
| 关系没有理由 | `addEdge` 直接返回 null，建不出来 |
